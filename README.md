# MAX Chat

Веб-чат для мессенджера MAX на сервисе [GREEN-API](https://green-api.com/max): отправка и получение текстовых сообщений в интерфейсе, повторяющем чат `web.max.ru`.

**Работающая версия: https://andreibobryk.github.io/max-chat/**

Стек: React 19, TypeScript, Vite, CSS Modules. Без UI-библиотек, стейт-менеджеров и собственного бэкенда — браузер обращается к GREEN-API напрямую.

## Запуск

```bash
npm install
npm run dev
```

Откройте адрес из консоли (по умолчанию `http://localhost:5173`) и введите `idInstance` и `apiTokenInstance` из [личного кабинета GREEN-API](https://console.green-api.com).

Проверено на Node.js 24.20 и npm 11.

## Что настроить в личном кабинете GREEN-API

Приложение не может проверить или изменить эти настройки само, поэтому их нужно выставить заранее. Изменения применяются до 5 минут.

- Инстанс авторизован в MAX: QR-код отсканирован.
- Поле `webhookUrl` пустое. Иначе уведомления уходят на этот адрес, а запрос на их получение отвечает ошибкой 400.
- Включено получение уведомлений о входящих сообщениях.
- Включено получение уведомлений о статусах отправленных сообщений и о сообщениях, отправленных через API. По ним ответ собеседника привязывается к нужному чату и показываются ошибки доставки.

## Как пользоваться

1. Введите `idInstance` и `apiTokenInstance`, нажмите «Войти».
2. Нажмите «+», введите номер телефона получателя и нажмите «Создать чат».
3. Напишите сообщение. `Enter` отправляет, `Shift+Enter` переносит строку.
4. Получатель отвечает в мессенджере MAX.
5. Ответ появляется в том же чате без перезагрузки страницы.

## Как это устроено

Используются только три метода GREEN-API:

| Метод | Зачем |
|---|---|
| [`sendMessage`](https://green-api.com/v3/docs/api/sending/SendMessage/) | отправка текста |
| [`receiveNotification`](https://green-api.com/v3/docs/api/receiving/technology-http-api/ReceiveNotification/) | получение очередного уведомления из очереди |
| [`deleteNotification`](https://green-api.com/v3/docs/api/receiving/technology-http-api/DeleteNotification/) | подтверждение, что уведомление обработано |

- **Вход.** Отдельного метода проверки учётных данных нет, поэтому вход проверяется первым запросом `receiveNotification`.
- **Получение.** Один цикл: получить уведомление, обработать, удалить. Очередь GREEN-API общая для всех типов событий и выдаёт их строго по порядку, поэтому удаляется каждое уведомление, включая ненужные. При сбоях цикл повторяет запрос с растущей паузой от 1 до 30 секунд.
- **Частота опроса.** При пустой очереди сервер удерживает запрос до 25 секунд и отвечает `null` — проверено на реальном инстансе в октябре 2026. На случай, если сервер ответит пустотой сразу, есть защита: следующий запрос уйдёт не раньше чем через секунду.
- **Адрес API.** Вычисляется из `idInstance`: `https://{первые 4 цифры}.api.green-api.com`. Если этот хост недоступен при входе, используется `https://api.green-api.com`.
- **Чат по номеру.** Сообщение уходит на `{номер}@c.us`. Ответ приходит с числовым идентификатором чата MAX, поэтому приложение сопоставляет его с чатом по номеру отправителя, а если номер скрыт — по идентификатору отправленного сообщения из уведомлений о статусе.
- **Хранение.** Учётные данные лежат в `sessionStorage` и исчезают при закрытии вкладки. История чатов лежит в `localStorage`: тремя методами выше её нельзя загрузить повторно.

### Если вход не удаётся из-за адреса API

Задайте адрес из поля `apiUrl` личного кабинета в файле `.env.local`:

```
VITE_GREEN_API_URL=https://3100.api.green-api.com
```

## Публикация

Сайт размещён на GitHub Pages: https://andreibobryk.github.io/max-chat/

`npm run deploy` собирает приложение с базовым адресом `/max-chat/` и отправляет содержимое `dist` отдельным коммитом в ветку `gh-pages`, из которой GitHub раздаёт сайт. Обновление появляется на сайте в течение нескольких минут.

На опубликованном сайте нет ни сервера, ни общих данных: учётные данные инстанса и переписка остаются в браузере того, кто их ввёл.

## Структура

```
scripts/         публикация на GitHub Pages
src/
├─ api/          клиент GREEN-API, разбор ошибок, цикл получения уведомлений
├─ domain/       номер телефона, разбор уведомлений, редьюсер чатов, тексты ошибок, даты
├─ state/        сеанс и чаты (контексты React), хранение в браузере
├─ components/   экран входа, список чатов, окно нового чата, переписка
├─ styles/       переменные оформления и общие стили
└─ test/         имитация GREEN-API и образцы уведомлений для тестов
```

## Тестирование

## Ограничения

- Только текстовые сообщения. Фото, стикеры, аудио и другие типы показываются заглушкой; подпись к фото или видео выводится под ней. Сообщения из групп и каналов не показываются.
- Отправка по номеру работает только для России (+7) и Беларуси (+375) — это ограничение GREEN-API.
- На тарифе Developer доступно 3 чата в месяц, причём `номер@c.us` и числовой идентификатор одного и того же собеседника считаются отдельно.
- История хранится только в этом браузере. Сообщения старше 24 часов, пришедшие при закрытом приложении, не восстановить: очередь GREEN-API хранит уведомления сутки.
- Очередь уведомлений у инстанса одна. Если её читает вторая вкладка или другая интеграция, сообщение может достаться не всем читателям. При проверке с двумя вкладками оно пришло в обе, но это не гарантируется: уведомление удаляет тот, кто обработал его первым.
- После обрыва связи индикатор «Нет соединения» гаснет не сразу: проходит остаток паузы между попытками и до 5 секунд ожидания ответа.
- Токен передаётся в адресе запроса — так устроен GREEN-API. Приложение не пишет его в консоль и не сохраняет дольше жизни вкладки.
