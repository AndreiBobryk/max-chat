# Ручные тест-кейсы

Приёмка приложения на реальном инстансе GREEN-API.

**Статус:** ручной прогон на реальном инстансе ещё не выполнялся. Колонка «Результат» заполняется при прогоне: «пройден», «не пройден» или комментарий.

## Как читать таблицы

- **Пр.** — приоритет: **P0** — требование ТЗ, **P1** — устойчивость, **P2** — желательно.
- **Автотест** — покрыто ли поведение автотестом на имитации GREEN-API (`npm run test`). «Да» не заменяет ручную проверку: имитация собрана по документации, а не по ответам настоящего сервиса.

## Что понадобится

- **Инстанс A** — авторизован в MAX, настройки из раздела README «Что настроить в личном кабинете GREEN-API» выставлены.
- **Телефон B** — аккаунт MAX с номером России или Беларуси, номер не скрыт в настройках приватности.
- **Номер N** — номер России или Беларуси без аккаунта MAX.
- Браузер с открытыми инструментами разработчика (вкладки Network и Console).

**Квота тарифа Developer — 3 чата в месяц**, причём `номер@c.us` и числовой идентификатор одного собеседника считаются отдельно. Прогоняйте кейсы на одном-двух получателях, кейс C10 выполняйте последним.

## Проверить в первую очередь

Эти допущения взяты из документации и на реальном инстансе не подтверждались. Если что-то из них неверно, часть кейсов ниже не пройдёт.

| № | Допущение | Как проверить | Результат |
|---|---|---|---|
| 1 | Адрес API получается из `idInstance`: `https://{первые 4 цифры}.api.green-api.com` | Сравнить с полем `apiUrl` в личном кабинете. При расхождении задать `VITE_GREEN_API_URL` | |
| 2 | При пустой очереди `receiveNotification` держит запрос открытым запрошенное время (5 с для первого запроса, 25 с для следующих) и отвечает пустым телом или `null` с кодом 200 | Вкладка Network: длительность и ответ запроса, после которого нет `deleteNotification`. Запросы, идущие подряд за миллисекунды, — признак того, что сервер не ждёт | |
| 3 | После отправки на `номер@c.us` уведомление о статусе содержит числовой `chatId` и тот же `idMessage`, что вернул `sendMessage` | Вкладка Network: сравнить ответ `sendMessage` и следующие ответы `receiveNotification` | |
| 4 | Отправка на `номер@c.us` и ответ с числовым `chatId` расходуют квоту как один чат или как два | Счётчик чатов в личном кабинете после кейса G01 | |
